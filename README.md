# ParkVision — керування паркуванням і лабораторія AI

Вебзастосунок для перевірки трьох готових моделей і базового обліку паркування:

- **LPR** — детектор рамки номерного знака.
- **OCR** — розпізнавання символів на обрізаному зображенні номера.
- **PKLot** — класифікація одного паркомісця як вільного або зайнятого.
- Реєстрація та вхід користувачів; звичайні користувачі бачать лише власні авто й історію, співробітники з роллю адміністратора можуть керувати реєстром, тарифами та чорним списком.
- Завантаження фото, перевірка номера за реєстром, фіксація послідовних подій в'їзду/виїзду, тривалості та розрахунку.
- Сповіщення в кабінеті при досягненні порогу витрат і CSV-звіт.

Інтерфейс побудований на Django, окремий сервіс inference — на FastAPI, база для розгортання — PostgreSQL. Усі моделі та зображення обробляються локально; завантажені фото не зберігаються.

## Швидкий запуск у Windows

Для Windows найпростіший варіант — запустити `start.bat`. Він створює ізольоване середовище `.venv` **в корені `WS`**, встановлює залежності з `requirements.txt`, виконує перевірку та міграції, потім відкриває окремі вікна Django і FastAPI. У VS Code для notebook виберіть kernel `WS\.venv\Scripts\python.exe`; після цього код проєкту не залежить від зовнішнього `C:\pv`.

Ручне створення середовища у корені проєкту:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate
```

Запустіть AI API в першому вікні:

```powershell
.venv\Scripts\python.exe -m uvicorn ai_api:app --host 127.0.0.1 --port 8001
```

У другому вікні запустіть вебінтерфейс:

```powershell
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Відкрийте [http://127.0.0.1:8000](http://127.0.0.1:8000), створіть обліковий запис. Для керування системою створіть адміністратора:

```powershell
.venv\Scripts\python.exe manage.py createsuperuser
```

Увійдіть як адміністратор; відкрийте **Адмінпанель**, щоб прив'язати номерний знак до користувача. Додайте номер також на сторінці **Номерні знаки**. Початковий тариф (50 грн/год, поріг 500 грн) створиться автоматично; його можна змінити в меню **Тарифи**. Вхідні тарифи зберігаються у гривнях, а неповна година округлюється вгору до повної години (мінімум одна година).

SQLite використовується лише для локального запуску та тестів. Для спільної роботи/розгортання запускайте PostgreSQL через Compose, див. нижче.

## Docker Compose і PostgreSQL

Потрібні Docker Engine та Docker Compose v2. Секрети `DJANGO_SECRET_KEY` і `POSTGRES_PASSWORD` обов'язкові: скопіюйте `.env.example` і замініть значення на випадкові секрети. Для публічного HTTPS-розгортання налаштуйте TLS reverse proxy та змінні `SECURE_COOKIES=1`, `SECURE_SSL_REDIRECT=1`, `SECURE_HSTS_SECONDS` (лише коли домен гарантовано працює тільки через HTTPS), `DJANGO_ALLOWED_HOSTS` і `CSRF_TRUSTED_ORIGINS`.

```powershell
Copy-Item .env.example .env
# Відредагуйте .env і задайте власні секрети
docker compose up --build
```

Сервіс автоматично очікує готовності PostgreSQL, виконує міграції та запускає Django. Compose за замовчуванням доступний локально через HTTP, тому `SECURE_COOKIES=0`; у TLS-розгортанні встановіть `SECURE_COOKIES=1` і завершуйте HTTPS на довіреному reverse proxy. Інтерфейс: [http://localhost:8000](http://localhost:8000). Для створення адміністратора:

```powershell
docker compose exec web python manage.py createsuperuser
```

Дані PostgreSQL зберігаються в named volume `postgres_data`. FastAPI доступний усередині Compose-мережі для Django на `ai:8001`; напряму в інтернет він не опублікований.

## Перевірка моделей

У лабораторії `main.py` можна перевірити наявні моделі локально. Основний сценарій обліку відкрийте у Django за пунктом **Розпізнати авто**: завантажте зображення, виберіть явно **В'їзд** або **Виїзд**, перевірте OCR і підтвердьте номер. Повторне фото з типом «В'їзд» не закриє сесію; вибір «Виїзд» без активної сесії не змінить облік.

На сторінці **Розпізнати авто** комбінація LPR+OCR шукає номер у реєстрі. Якщо OCR помилився, виправте номер перед фіксацією події. Перше використання кожної моделі може зайняти більше часу через завантаження ваг у пам'ять.

Окрему лабораторію для перевірки моделей можна запустити з єдиного файлу `main.py`:

```powershell
.venv\Scripts\python.exe main.py
```

Вона відкривається за адресою [http://127.0.0.1:7860](http://127.0.0.1:7860). Якщо навчені ваги відсутні, спершу виконайте потрібні клітинки ноутбука. Під час запуску через Docker Compose лабораторія доступна на порту 7860.

## Навчання моделей у ноутбуці

Notebook навчає **детектор на ELPD** та OCR на синтетичних українських табличках формату `LLDDDDLL`. ELPD містить лише рамки номерів і не має транскрипцій символів, тому не є навчальним набором для OCR. Поточний OCR не підтримує загальні європейські формати, зокрема німецькі номери; його score не є каліброваною ймовірністю правильного розпізнавання. Для навчання OCR на потрібному форматі потрібні обрізані зображення номерів із точними текстовими мітками. Розмістіть ELPD як `data/raw/elpd.zip` або розпакуйте його в `data/raw/elpd/`, виберіть kernel `.venv\Scripts\python.exe` на Windows і послідовно запустіть `ParkVision_AI_Training.ipynb`. Notebook перевіряє YOLO-анотації, створює відтворюваний split 70/15/15, навчає обидві моделі, вимірює mAP, OCR character accuracy, CER та точне співпадіння цілого номера. Ваги зберігаються у `data/models/lpr_detector.pt` і `data/models/ukrainian_lp_sequence_model.keras`; символи — у `data/models/ukrainian_lp_characters.json`; метрики — у `data/models/*_test_metrics.json`. Реальну точність оцінює лише незалежний labeled набір `data/real_ocr_test/labels.csv`, якщо він наданий.

Для LPR використовується [European License Plate Dataset (ELPD)](https://www.kaggle.com/datasets/tielemarvin/european-license-plate-dataset-elpd), заявлена автором ліцензія [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). У локальній копії перевірено 2 329 зображень і 2 286 файлів міток; точні придатні кількості та SHA-256 fingerprint split друкує notebook. Під час поширення моделі атрибутуйте Marvin Tiele та набір ELPD і вкажіть ліцензію. Набір синтетичний і обмежений: test-оцінка не замінює незалежний тест на реальних українських зображеннях.

Запуск JupyterLab з локального середовища:

```powershell
.venv\Scripts\python.exe -m jupyter lab
```

Навчання на CPU може бути тривалим; notebook повідомляє фактичні метрики test split. Збільшення кількості епох не замінює різноманітних незалежних навчальних даних.

## Відомі обмеження

- У лабораторії LPR+OCR і класифікатор паркомісця запускаються однією дією, але це окремі спеціалізовані моделі; для класифікації зайнятості необхідне окреме фото одного паркомісця.
- ELPD містить синтетичні європейські сцени; детектор потрібно незалежно перевірити на реальних українських зображеннях до використання для обліку платежів.
- Результати навчання залежать від апаратного забезпечення, версій бібліотек і конкретних архівів; для оцінювання дивіться метрики окремого test-набору в ноутбуці, а не лише точність на train.
- OCR залежить від чіткого, рівного обрізаного зображення та може помилятися; перевіряйте номер перед збереженням події.
- Сповіщення про перевищення порогу формуються під час наступного відкриття кабінету або розпізнавання події; для гарантованої доставки в реальному часі потрібен фоновий планувальник/канал повідомлень.
- Вебкамера, фізичне керування шлагбаумом, push/email-повідомлення та інтеграція з платіжною системою не реалізовані.
- TensorFlow у цій інсталяції Windows виконується на CPU; використання GPU залежить від ОС і сумісного runtime.
